---
name: claudemd-audit
description: Aggregate claudemd rule-hits over the last N days. Shows top banned patterns, hook deny counts, per-spec-section heatmap, and bypass-escape-hatch usage.
---

Default window is 30 days. The command's argument (`$ARGUMENTS`) is an optional day count; pass it as `--days=N`.

Run: `node ${CLAUDE_PLUGIN_ROOT}/scripts/audit.js [--days=N]`

The JSON contains:

| Field | Meaning |
|---|---|
| `byHook` | per-hook total + event breakdown — answers "which hook is firing" |
| `bySection` | per-spec-section total + event/hook breakdown — answers "which spec rule is firing" (drives §0.1/§13.1/§13.2 promotion/demotion accounting). Null-section rows split by cutoverTs: `(unset-historical)` = rows from before sections were recorded (will age out), `(unset-current)` = post-cutover null-section (mix of intentional housekeeping events + instrumentation gaps). |
| `byBypass` | per-token bypass-escape-hatch usage — high counts signal a rule that's too strict and is being routinely overridden. Each token also carries `bySubject`: WHAT the hatch was used against (`vars:<NAME>` / a runner / a rule slug / a `shape:source->sink`). A token count alone cannot separate 12 overrides of one badly-worded rule from 12 unrelated one-offs, and those imply opposite actions — read `bySubject` before proposing a demote. Rows written before the field existed group under `(no subject)`; a series spanning that boundary is split, not averaged. Each token also carries `suppressed: {yes, no, unrecorded}` — whether the hatch actually avoided a deny. The §8 `allow-rm-rf-var` row records it (the token also counts when it only appears as data, e.g. in a heredoc or commit message); `unrecorded` is older rows and hatches that do not emit the field, not `no`. |
| `uniqueInvocations` | per-hook dedup view: `rows` = raw row count; `unique_invocations` = distinct `(ts, hook, session_id, tool_use_id, event, extra)` tuples (multi-emit hooks like pre-bash-safety log one row per matched pattern in a compound command, so event+extra are needed to separate legit multi-emit from a real double-fire); `duplicate_rows` = rows−unique (back-compat sum); `duplicate_rows_real` = dupes where colliding row has non-null `tool_use_id` AND is byte-identical (same event+extra) to an earlier row in the same invocation (= true single-invocation double-fire signal — registration/lib bug candidate when on PreToolUse/PostToolUse, but see the multi-emit caveat below); `duplicate_rows_legacy` = dupes where colliding row has null `tool_use_id` (= seconds-precision collision noise from old rows without tool ids, OR expected Stop/SessionStart-class same-second-same-session hits); `legacy_rows` = rows with both session_id+tool_use_id null (the noise floor). |
| `dataIntegrity.cutoverTs` | ISO-8601 UTC of the earliest row carrying a non-null `spec_section`; null when no row in the log has one. Drives the `bySection` cutover-split. |
| `dataIntegrity.testSessionsFiltered` | count of test-sentinel rows stripped from every view: `session_id='t'/'test'` (hook unit-test sentinels) plus any non-null session_id ≤7 chars (ad-hoc manual-debug sentinels like `'s'`/`'probe'`; real CC ids are 36-char UUIDs). Lets the operator confirm filter ran + quantify test traffic; raw byHook/bySection numbers in the same payload are post-filter, real-session-only. It also strips `pre-bash-safety` decision rows (`deny` / `rm-rf-allow-*` / `bypass-escape-hatch`) that carry `hook_version` but neither `session_id` nor `tool_use_id` — a real PreToolUse event always has the id, so those are hand-fed probes. |
| `byFailOpen` | per-hook fail-open rows: `total`, `byReason`, and `notApplicable` (the gate had nothing to evaluate — `mem-index-missing`, a project with no MEMORY.md) vs `blind` (every other reason, including unclassified ones). Report `blind`; `notApplicable` is not a bypass. |
| `topPatterns` | banned-vocab matched-word ranking |
| `denyByProjectClass` | per-hook **blocking-deny** (`deny`/`deny-repeat`/`deny-prose`; excludes `deny-prose-dry-run`) split into `self` (the plugin dogfooding itself — project path ends in `-claudemd`) / `external` (real downstream repos) / `unknown` (no project field). Raw deny counts overstate enforcement value when claudemd's own repo dominates traffic (banned-vocab ~498/516 historically self). |
| `selfCompliance` | self-enforced-rule counts from the retrospective transcript scan of the CURRENT project (same window; wraps `scripts/sampling-audit.js`, 8 detectors). Per rule: `opportunities` / `violations` / `rate` / `precision` / `status`. `rate` and `precision` are null and `status` is `collecting`: the hand-labeling track that would calibrate the detectors closed on 2026-07-24 at pooled precision ≤ 0.17 (OPERATOR.md), so these counts are collection data. |

For `denyByProjectClass`: report each hook's deny split as `<external> external / <self> self / <unknown> unknown` and **lead with the `external` count as the real downstream-interception signal** — do NOT present the raw deny total as the enforcement value (most of it is the plugin's own dogfood; see the 498/516 banned-vocab finding).

Format per-hook sections, the bySection heatmap (sorted by total desc), and call out any `byBypass` token with ≥3 occurrences as "review candidate" (where `suppressed` is recorded, count `suppressed.yes`, not `total`) per the OPERATOR.md §13.1 demotion review, and for each such token print its top `bySubject` entries — the subject is what makes the candidate actionable ("`vars:SCRATCH` ×9" is a gate mis-shaped for sandbox cleanup; nine different subjects is nine one-offs and no rule change). If a token's subjects are all `(no subject)`, say so rather than inferring — those rows predate the field. Surface `uniqueInvocations.<hook>.duplicate_rows_real > 0` for any PreToolUse/PostToolUse hook as a candidate registration/lib bug — EXCEPT for multi-emit hooks (pre-bash-safety logs one row per matched pattern in a compound command), where a residual `_real` can come from one command repeating the SAME pattern (`rm -rf $D; …; rm -rf $D`); telemetry can't distinguish that from a double-registration, so confirm against the source command before reporting a bug. **Do NOT report bare `duplicate_rows`** — that number includes legacy collision noise (`duplicate_rows_legacy`) which is expected for rows without tool ids and for Stop/SessionStart-class hooks. Always read the `_real` / `_legacy` split, never the bare sum.

For `bySection['(unset-historical)']`: note as legacy data from before sections were recorded — will age out of the window naturally; do NOT include in the heatmap leader.

For `selfCompliance`: report `violations/opportunities` per rule verbatim (denominators are mandatory — a bare hit count is not evidence). Do not present the ratio as a compliance rate or draw conclusions from it — say "collection data, detectors uncalibrated"; a compliance judgment needs manual review of the transcripts.

For `bySection['(unset-current)']`: subtract by-design housekeeping events (`session-start` `bootstrap` / `upstream-banner`, `user-prompt-submit` `version-sync`) before judging — the residual is the actual instrumentation-gap signal. List the residual hook+event combos as "post-cutover null-section, expected vs gap" so the operator can spot which hooks still emit without a section despite recording sections.
