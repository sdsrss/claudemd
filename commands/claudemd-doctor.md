---
name: claudemd-doctor
description: Health check of the claudemd install — dependencies, spec and hook drift, settings.json, backups, rule usage and memory hygiene. Supports --prune-backups=N and --ack-fail-open.
disable-model-invocation: true
---

Usage: `/claudemd-doctor`, `/claudemd-doctor --prune-backups=5` or `/claudemd-doctor --ack-fail-open`

Run: `node ${CLAUDE_PLUGIN_ROOT}/scripts/doctor.js $ARGUMENTS`

Surface the checks list with [✓] / [△] / [✗] prefixes based on the `ok` field. If `pruned` is non-empty, list the removed backup directories. If `pruneSkippedLegacy` is non-empty, say so separately: those are pre-0.68.3 spec-shaped dirs sitting in the personal backup namespace — the prune deliberately neither deleted them nor counted them toward N, and the `backup-namespace-legacy` check above explains why the user has to sort them by hand. Reporting only `pruned` hides the half of the story that needs a decision.

For `hook-fail-open` when `ok=false`: a hook skipped enforcement and recorded why; the detail lists each hook and reason. Most reasons are a prerequisite the user can restore (`jq`, a patterns file, a writable `~/.claude/.claudemd-state/`). `transcript-missing` and `event-fields-missing` mean a hook could not locate the session transcript or the event fields it reads: a `CLAUDE_CONFIG_DIR` that moves transcripts out of `~/.claude/projects`, or sessions run without transcripts, cause the first, and a change in what Claude Code writes or sends can cause either, which no local setting fixes. Say which applies when you can tell. Help the user fix what can be fixed; while a cause persists, each new row turns the check red again, so acknowledging does not clear it. Run `--ack-fail-open` only after the user says the cause is fixed, never to turn the check green on your own. It records each fail-open event the row counts, by its time, hook and reason, in `fail-open-ack.json` in doctor's state directory (`~/.claude/.claudemd-state/` unless `CLAUDEMD_STATE_DIR` names another; the hooks always use `~/.claude/.claudemd-state/`); those stop counting, and any other such event turns the row red again. That is how a cause that is not fixed shows itself: the next time the affected hook skips enforcement it records a new one (while it can write to `~/.claude/.claudemd-state/`, at most one a minute per hook and reason). Report `failOpenAck`: `written` and `acknowledged` (how many it newly acknowledged), or the `reason` nothing was written. If doctor exits 1 with `cannot write the fail-open acknowledgement`, nothing was acknowledged or pruned and there is no check list: show the message. The error code at its end says why: `EACCES` or `EROFS` means the directory it names is not writable (when that is `~/.claude/.claudemd-state/`, that is itself a cause of fail-open); `EISDIR` means a directory sits at the file's path; `EEXIST` or `ENOTDIR` means a file sits where the state directory or one of its parents should be.

For `memory-tag-specificity` check: when `ok=false`, present the candidate list, group by memory file, and cite spec §11-EXT Tag-specificity (SHOULD, v6.11.11). Suggest the rename pattern shown in the detail (`impact`→`impact-analysis`, etc.). Advisory only — operator decides per case.

For `memory-index-size`: each `MEMORY.md` is judged against the 12KB soft default, or against a budget it declares itself with a whole-line HTML comment — `<!-- index-budget: 32KB -->` — anywhere outside a code block. Declare one when the overage is a decision rather than a backlog: the tags are the routing keys the §11 hint hook matches on, so compressing them buys bytes by spending recall, and `feedback_*` entries with no recent hits are usually safety rules whose quiet is normal. The declared number is printed in the line it makes green, so raising it stays visible; it is capped at 16× the default, and a malformed declaration (`28` with no unit, `28 KB` with a space, an unclosed comment) **fails the check** rather than reverting to the default in silence.

For the three `memory-maintenance:*` checks (wrong-layer memory placement fails silently): `promote` lists claude-mem-lite lessons cited ≥3× and alive ≥30d (high-frequency recall = de-facto durable knowledge → candidate MEMORY.md entry); `recall-repatriation` lists durable `recall_*.md` plugin-absent fallback files older than 30d (migrate into mem-lite or delete); `stale` lists durable files >90d with zero keyword mentions in the telemetry window (review tags per §11-EXT or retire). **All three are candidates only — never migrate/delete automatically; migration is a §5-scoped write and the operator's call.** `promote` degrades gracefully (`skipped: …`) when the mem-lite DB or `node:sqlite` is unavailable.
