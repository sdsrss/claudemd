# D#652：cache prune 读 Claude Code 的 `.in_use/<pid>`

状态：已完成（提交在本地 `next-release`，未推送）

## 背景与目标

- 0.117.6 发版后，使用者说"之后的批次：D#652（让 cache prune 读 .in_use/<pid>）和 D#598（11-28 前再存一次快照）。把这两个做了"。本文件只管 D#652；D#598 是只读扫描，结果记在延期项里。
- 0.117.6 发版前评审 M2：`scripts/lib/cache-prune.js` 只读 `.orphaned_at` 和 hook 日志。只在另一个会话的环境里设了 `DISABLE_RULE_HITS_LOG=1` 时，安装仍可能删掉一个正在被会话使用的旧版本目录（那个会话的 hook 全部 exit 127，D#635 的故障）。
- 目标：候选目录里只要 `.in_use/` 有一个条目指向活着的进程，就保留，原因 `in-use`。

## 调查结果（2026-11-02）

- 官方文档 code.claude.com/docs/en/plugins/loading 的 "Cleanup of previous versions" 只写 `.orphaned_at`，没有 `.in_use`。
- 本机 Claude Code 2.1.316 的程序代码（`~/.local/share/claude/versions/2.1.316`，打包的 JS）：
  - 每个进程在它加载的版本目录写 `.in_use/<pid>`，内容 `{"pid":N,"procStart":"…"}`（Windows 用 `procStartFt`），退出时删自己的。
  - procStart：Linux 取 `/proc/<pid>/stat` 最后一个 `)` 之后按空格切开的第 20 项（即第 22 个字段 starttime）；macOS 取 `LC_ALL=C TZ=UTC ps -o lstart= -p <pid>`。
  - 判活（`LLt`）：pid 为 1 或 `process.kill(pid,0)` 成功；有 procStart 时，现读的值读不到也算活，读到则必须相等。不活的条目被它删掉；读不了的条目算活；JSON 解析失败的条目被删掉。
  - 自己的 14 天清理（`Cms`）：按 `.orphaned_at` 的 mtime 计时，满 14 天后先查 `.in_use`，有活进程就跳过（日志 "Skipping orphan cleanup, in use by live session"）。所以"Claude Code 标记 14 天后会删"要加上"除非有活会话"。
  - 2.1.309、2.1.310 也有这段代码。
- 本机：0.117.1 有 2 个条目、0.117.3 有 4 个、0.117.6 有 1 个，全部是活着的 `claude` 进程，procStart 与 `/proc/<pid>/stat` 第 22 字段一致。同一 pid 同时出现在 0.117.1 与 0.117.3：换版本后旧条目留到进程退出，按它保留只会多留，方向安全。

## 范围

- 做：`scripts/lib/cache-prune.js`（新判据与注释）；`tests/scripts/cache-prune.test.js`；`commands/claudemd-install.md` 第 20 行（第四种原因，修正"Claude Code 14 天后删"一句）；`tests/scripts/command-page-behaviour.test.js` 锁这一行并跑出第四种原因。CHANGELOG 在发版时写。

## 方案

- 判定顺序：`in-use` → `orphaned-recently` → `hook-rows-recently` → `no-log-signal` → 删除。`in-use` 放第一：它是直接证据，另三个是推测；也只有它能在标记满 14 天后继续保留（与 Claude Code 自己的清理一致）。现有用例没有 `.in_use`，它们的原因不变。
- 判活：pid 必须是正整数（防 `kill(0)`、`kill(-n)` 发到进程组）；`process.kill(pid,0)` 抛 `EPERM` 算活（进程存在，只是不归我们），其他错误算死。有 procStart 字符串且 `/proc/<pid>/stat` 读得到时必须相等；读不到（macOS，或进程刚退出）算活，与 Claude Code 一致。
- 条目读不了或解析不了：不算活。与 Claude Code 对解析失败的处理一致；它对"读不了"算活，但这些文件是同一用户写的，读失败只在条目刚被删除时发生（ENOENT），不另设分支。
- 返回形状不变：`{ name, reason }`。
