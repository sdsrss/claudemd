## 方案（D#433）
只在结束时还有未验证改动、且 cwd 在 git 仓库里时才问 git；git 任何失败或超时，一条都不丢。
1. stash：`for-each-ref refs/stash` 一次调用；有 stash 且晚于本轮提示（或不知道提示时间）→ 不过滤。
2. 逐条把目标按物理路径解析：目录用 `cd -P`（在当前 shell 里，不 fork），文件本身是符号链接 → 保留（编辑可能经它改了别处）；物理路径不在 git 顶层之下 → 保留。这回答了评审 M（经仓库内符号链接的编辑、指向仓库外的目录链接）。
3. `ls-files -v -z` 与 `status --porcelain=v1 -z --untracked-files=no` 只问这些路径（`--literal-pathspecs`），路径作为独立参数传给 git，结果经标准输入交给 jq，不再用 `--argjson`（回答 128 KiB 单参数上限）。
4. 判定"已回到 HEAD"：status 没列出它，且（文件存在并以 `H` 标记被跟踪）或（文件不存在、也不在索引里）。assume-unchanged（小写标记）、skip-worktree（`S`）、未合并等都不是 `H` → 保留。未跟踪、被忽略、子模块里、`.git/` 里的文件都不是"被跟踪"→ 保留。大小写不一致（APFS）时按字符串精确匹配失败 → 保留。
5. 每个 git 调用都包 `platform_timeout 0.5`，三次最多 1.5 秒，在 SessionEnd 的 3 秒预算内（回答"未限时的 git 调用"）。macOS watchdog 只杀它启动的那个进程：直接调用 git 时那就是 git 本身。
6. 触发条件改为 OPEN > 0（过滤后可能为 0）；检查点列出过滤后的最后三条；`docs/RULE-HITS-SCHEMA.md` 的 `open` 字段说明随之更新。
