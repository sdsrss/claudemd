# D#643 + D#644：cache prune 在日志关闭时的保留、restore 跳过没有 CLAUDE.md 的规范备份

状态：已完成

## 背景与目标

- 0.117.5 发版后，使用者回复"剩下的这几项工作现在就做了"，指的是延期项 D#643、D#644（各自带着我的建议做法）。
- D#643：`scripts/lib/cache-prune.js` 在两种情况下保留旧版本目录：`.orphaned_at` 标记不到 14 天，或日志 14 天内有该版本的行。设了 `DISABLE_RULE_HITS_LOG=1` 时 hook 不写日志，第二个信号永远为空，没有标记、却仍被某个会话使用的目录会被删掉，那个会话的 hook 全部 exit 127，§8 闸门失效（D#635 的故障）。
- D#644：restore 跳过较新的规范备份，判据是 `holdsOnlySpecFiles`（`scripts/lib/backup.js`），要求目录里有 `CLAUDE.md`。0.68.3 以前的 `/claudemd-update` 在 `CLAUDE.md` 没变时写出没有 `CLAUDE.md` 的规范备份（v0.68.2 之前 47 个改动规范的版本步里有 2 个，0.116.6 第 2 轮评审复现）；d39c4b2（2026-10-16）以前的 install 在家目录没有 `CLAUDE.md`、只有规范同级文件时也写出这种目录（R15）。restore 取回它，使用者更早的个人备份回不来（0.117.5 评审 M1 的复现）。

## 范围

- 做：`scripts/lib/cache-prune.js`（日志关闭时保留没有标记的候选目录，原因 `no-log-signal`）；`scripts/lib/backup.js` 的 `holdsOnlySpecFiles`（不再要求 `CLAUDE.md`，要求至少一个条目）；对应注释；`commands/claudemd-install.md`、`commands/claudemd-uninstall.md`、`README.md` 描述这两处的句子；测试。CHANGELOG 条目在发版时写（本仓库没有 `[Unreleased]` 节）。
- 不做：日志开着、但 14 天内一行都没有的情形（例如日志被删）：要改动以"保留 3 个"为题的现有用例夹具，且实际少见，照旧删除，写进"未改动"；空目录或只有 `hooks/` 的目录挡住 restore（0.116.6 第 2 轮 L1）；doctor 的 `backup-namespace-legacy` 行（只列含规范 `CLAUDE.md` 的目录，判据改动不改变它的输出）；发版（等使用者决定）。

## 方案

- cache prune：判定顺序不变（标记 → 日志行 → 删除），在删除前加一步：`process.env.DISABLE_RULE_HITS_LOG === '1'`（与 `hooks/lib/hook-common.sh:484` 的判定相同）且目录没有标记时，保留并记 `no-log-signal`。有标记的目录不受影响：Claude Code 标记 14 天后自己也会删它，说明那时已没有会话在用。代价：这类目录（每个约 11 MB）一直留到有了标记或被手动删除。
- restore 判据：安全性不靠"有没有 `CLAUDE.md`"，而靠"每个条目的第一行都是规范标题"：使用者手写的文件过不了这一条，所以含个人文件的目录不会被跳过。现在的 install 在没有 `CLAUDE.md` 时只有遇到非 claudemd 的同级文件才写个人备份（`scripts/install.js` 的 `onlySpecSiblings`），那个文件过不了判据。空目录：`every` 对空数组为真，所以要求至少一个条目，保持空目录的现有行为。
- doctor：`backup-namespace-legacy` 只列含规范 `CLAUDE.md` 的目录，对它们判据结果不变。
