# v7.1 — core room, delegation default in core, mid-turn stop rewrite

Source: docs/audit/20260926-180700.md (11.6 B6/B7 notes, 8.3 items 1–3); user go-ahead 2026-09-27 ("按你的建议执行 v7.1 批次").

## goal

1. Free core bytes without changing any rule's meaning (core 24,990/25,000 B at v7.0.0).
2. Put the delegation default where every session reads it. v6.36.0 rewrote it in §11-O, which now lives in `orchestrate.md`; that module is injected only when the prompt says "subagent / 并行 / fan out", so an ordinary task never sees it — and core §2.1 still says `2+ disjoint tasks → Agent`.
3. Rewrite core §11's mid-turn stop clause in behavioural terms (what stops are not allowed, which are), per the Opus 5.5 prompting guide; stop the typo prompt ("Fix the typo …") injecting `debug.md`.

## non-goals

- The other items v7.0.0 deferred: §4/§12 routing dedupe in `skills.md`, the extended stub, `hard-rules.json` `file` field, `/claudemd-update` module preview.
- No HARD rule added or removed. No rule ID renamed.
- No change to hooks other than the `debug` trigger.

## constraints

- Spec self-edit = L3 (LLM-visible). Proposal → diff → user ASK before merge (§13 META). Work on branch `v7.1-core`; nothing merged to main or released without the user's go-ahead.
- Byte caps: core ≤ 25,000; modules ≤ 9 KB each, 50 KB total (v7.0.0).
- Every HARD anchor in `spec/hard-rules.json` stays findable exactly once in core + modules.
- Moving text out of core is allowed only for text that already has a home in a module and is not needed to decide what to do at the start of a task (B6 lesson: a rule in a module is invisible to tasks that do not trigger it).

## harness finding (2026-09-27, before any spec edit)

`~/.bashrc` exports `CLAUDE_CODE_COORDINATOR_MODE=1`, and `scripts/offline-eval/run.mjs` passed `process.env` through. Every B4–B7 run was a coordinator session: main had 6 tools (Task, ListAgents, SendMessage, Skill, TaskStop, Workflow), no Read/Edit/Bash, and one `worker` agent type. Probe (Haiku, same flags): with the variable 6 tools, `agents: [worker]`; without it 27 tools, `agents: [claude, Explore, general-purpose, Plan, statusline-setup]`. So B6's "1 subagent in 20/20 runs, both arms" was forced by the environment and says nothing about the spec. This interactive session, launched with the same variable, has the full tool set, so the harness should run without it. The runs also inherited this session's linkage variables (`CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_MESSAGING_*`).

## success-criteria

1. Core ≤ 23,800 B after all three parts (≥ 1,190 B headroom), `npm run check` green, `spec-coherence-audit --strict` no new finding, `npm run smoke` green.
2. Offline A/B, harness without coordinator mode, Opus 5.5 high, 5 runs per task per arm; A = v7.0.0 (main), B = this branch:
   - over-delegation tasks (a multi-file rename, a where-is-X question, the L1 bugfix): B's subagent spawns per run ≤ A's, and B spawns in at most 1 of 5 runs per task. If A already spawns in ≤ 1 of 5, the delegation claim is recorded as "no over-delegation to remove in this harness" — not as a win;
   - T6 (review needs a fresh subagent): B spawns in ≥ 4/5 (the delegation line must not suppress required reviews);
   - T4, T8: B 5/5; every other task: B passes ≥ A − 1;
   - T1: B injects no `debug` module in 5/5.
3. Mid-turn stop: a multi-step task (T9) finishing every step in one turn: B ≥ A − 1. No win is claimed from it unless A actually stops early.
