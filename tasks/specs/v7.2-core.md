# v7.2 — 核心精简：去重、与 harness 对齐、维护者文字移出模型视野

来源：2026-09-29 会话，用户要求"在不影响功能的情况下精简全局核心规范"。三路证据：网络研究（官方文档 + 论文）、本机 224 个交互会话的使用数据、核心与 harness 系统提示词的逐条对照。工作在分支 `v7.2-core-draft`（草稿区 worktree），未合并、未发布。

## goal

1. 删掉核心里的重复：核心内部重复、与 Claude Code 系统提示词（2.1.285）重复、只给维护者看的说明。规则含义不变。
2. 消除一处与 harness 的冲突：核心 §11 把"上下文压力"列为可中途停下的理由，harness 说上下文会自动压缩、不必提前收尾。
3. 把几乎从不触发的细则移进已有模块，核心留一行可执行的默认。
4. 维护者专用行放进 HTML 注释：Claude Code 注入前会剥掉块级 HTML 注释（官方文档；本机已验证：本项目 CLAUDE.md 盘上 4 行 `<!--`，送进子代理的副本里 0 行）。

## non-goals

- 不动 §1 Language contract 和 §7 的"中文 user"条目：D#72 lang-drift 预注册窗口到 ~2026-10-26，§1 是它的主要混杂因素。
- 不增删 HARD 规则，不改规则 ID，不改 §8 任何规则的含义。
- 不把"符号 → 文字"的全文改写放进本批：研究显示符号只占核心 4.1% 字节，改写最多省几百 token；v7 已把 § 标签泄漏从 31.3% 降到 5.1%。
- 不改 hooks。

## constraints

- 核心 ≤ 25,000 B；模块各 ≤ 9 KB；extended ≤ 50,000 B（实施后 extended 48,629 → 49,082 B，+453 B，98.2%，仍在上限内；做法是缩短移入的 §3-EXT 文字和 Recent changes 条目，§0.1）。
- 每个 HARD 锚点在核心 + 模块里仍恰好出现一次。
- B6 教训：规则移进无触发的模块就看不见。只移"任务开始时不需要"的细节，核心保留可执行的一行。
- spec 自改 = L3（LLM 可见）：草稿 → A/B → 用户确认后才实施、合并、发布。
