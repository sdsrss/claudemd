### Critical

#### 6.0 §8 白名单臂缺 `..` 守卫，可删除白名单根之外的路径

**来源**：r16-algo H-1（其定级 High）。**lead 上调为 Critical**，理由见下。

`hooks/pre-bash-safety-check.sh` 的白名单臂（`:983-999`）规则是"白名单变量 + 字面子路径 ⇒ 放行"，
而 `..` 被当作字面子路径的一部分接受，于是路径逃出白名单根。
provenance 臂在 `:1191-1193` **有**这个守卫；白名单臂没有。

**lead 独立复核**（只问判决、从不执行；用例串经 Write 工具落盘，未出现在任何执行的命令行上；
沙箱 `HOME`/`TMPDIR`）：

| 用例 | 判决 | 命令（作为数据） |
|---|---|---|
| H-1a | **allow** | `rm -rf "$HOME/../victim"` |
| H-1b | **allow** | `rm -rf "$TMPDIR/../home/ai"` |
| ctl-literal-sub | allow | `rm -rf "$HOME/victim"`（白名单臂既定策略，正确） |
| ctl-bare-var | deny | `rm -rf "$D"` |
| ctl-validated | allow | `rm -rf "${D:?}"`（§8 记载的正确拼法） |
| ctl-bare-home | deny | `rm -rf "$HOME"` |
| M-tmpdir-plain | allow | `rm -rf "$TMPDIR/sub"` |
| M-tmpdir-default | **deny** | `rm -rf "${TMPDIR:-/tmp}/sub"` |

对照组证明闸门整体是活的——它按设计拒裸变量、放行已校验拼法——所以放行不是闸门失效，
是这一条臂的规则本身可被 `..` 绕开。`$HOME/../victim` 解析为 `/home/victim`；
`$TMPDIR/../home/ai` 直达用户家目录。r16-algo 另有沙箱实证删除。

**为何定 Critical 而非 High**（与报告者不同，理由照录以便复议）：

1. §8 是规范中**唯一标注 immutable、never exempt** 的一节，HACK / EMERGENCY / AUTONOMOUS 均不豁免。
2. 本项目 `AUTONOMY_LEVEL: aggressive` 且运行于 `bypassPermissions`，该闸门是**最后一道**控制，
   不是纵深防御中的一层。
3. 缺陷形状正是规范 §9 **Parallel-path completeness（HARD）** 所针对的：同一节点两条并行臂，
   守卫只装了一条。修法已知且局部——把 `:1191-1193` 的守卫补到 `:983-999`。
4. 唯一本可抓到它的语料控制项测的是反的性质（§6.5.1），所以它不是"新引入"而是"从未被覆盖"。

**最后一行的不对称方向是反的**：更安全、更可移植、且本仓库脚本（含 lead 本轮全部探针）
惯用的 `${TMPDIR:-/tmp}/sub` 被拒，裸 `$TMPDIR/sub` 被放行。它把作者推向较差的拼法。

**处置约束**：在本条修复前，不得合入 §6.5.3 的放宽方向改动——那次回放只测了 FP 方向。

#### 6.8 `platform_timeout` 在命令替换中是墙钟下界（r16-hooks H-1，**平台条件性 + 间歇性**）

`hooks/lib/platform.sh:47-61` 的纯 bash 看门狗：`( sleep "$secs" …; kill … ) &` 之后
`wait "$cmd_pid"` 对轻量命令几乎立即返回，于是 `kill -TERM "$watch_pid"` 与子 shell fork 出 `sleep`
形成**竞态**。输掉竞态时孤儿 `sleep` 存活并持有命令替换管道的写端，而 `$( )` 等待所有写端关闭。

| 测量 | 值 |
|---|---|
| lead，`cmd=true`，`secs=5`，n=30 | blocked >1000ms **28/30**，min 1ms，max 5014ms |
| r16-hooks，机制臂，`secs=1` n=30 + `secs=5` n=10 | **40/40** |
| **合并** | **68/70 ≈ 97%** |
| r16-hooks，SessionStart `NO_TIMEOUT_BIN=1`，n=10 | 中位数 **3212ms**（对照 0：314ms），slow 10/10 |
| r16-hooks，ship-baseline `NO_TIMEOUT_BIN=1`，n=10 | 中位数 **2213ms**（对照 0：216ms），slow 10/10 |

**作用域（决定定级）**：`platform.sh:41-44` 在 `timeout`/`gtimeout` 任一存在时先行 return，
故该分支在**任何装有 coreutils 的宿主上生产不可达**。暴露面为无 coreutils 的原生 macOS，
以及手动设 `CLAUDEMD_NO_TIMEOUT_BIN=1` 者。仓库带 macOS CI leg，故仍属真实缺陷。

**两个分母不一致，故并列而非择优**：lead 28/30 与 r16-hooks 40/40 同宿主、不同探针形状，
差异归因于探针形状或调度噪声而非机制。取更保守的 lead 数字作为读者判据：
**单次尝试约有 1/14 的概率返回 1ms**，这正是 lead 首次复核发生的事；**n≥10 是相信任一结论的门槛**。
本轮两侧的单次采样读数都错了，且错向相反——r16-hooks 的读作确定性，lead 的读作不存在。

**已证伪的假设，记录以免重试**：写不写 stdout 无关（`true` 与 `echo` 同样卡满）；
内建 vs 外部命令从来不是那条轴（`type -t` 显示两者皆为 builtin）。

**修法（随竞态模型而来）**：让看门狗的 sleeper 继承 `>/dev/null` 即可闭合，无论谁赢竞态；
进程组 kill 做不到这一点。其测试需要分母——单次快采样从任一侧读起来都像确定性。

**未测量**：原生 macOS 上的实际发生率——双方均无该宿主。

## 7. 本轮方法事故与教训

本节记录的两起事故均由本轮审计自身产生。写下来是因为它们比本轮多数发现更可能重演。

### 7.1 一次探针写入了维护者的实盘状态

**事件**：`2026-09-13T07:06:02Z`，`~/.claude/.claudemd-state/hook-root.json` 被写为
`{"root":"/home/ai/dev/claudemd","ts":"…","version":"0.85.0","sid":"repro-r16"}`。
日志行 `session-start | compact-reminder | sid repro-r16` 指认写入者：有人以真实 `$HOME`
运行了 `session-start-check.sh` 的 compact 分支。

**排除项**：仓库自身套件（`tests/hooks/session-start.test.sh:13-14` 有 `mktemp -d` 沙箱与 trap，
Case 40 用 sid `root-t`）、`r16-hooks`（列举全部 sid，日志零命中）、`r16-scripts`（从未执行过钩子，
三条路径机械核查）。归因未完全闭合。

**根因（r16-scripts M-5，lead 四臂复现）**：仓库已有"跑钩子而不污染全局"的惯用法
`DISABLE_RULE_HITS_LOG=1`（`doctor-hook-tests.js:181` 在用），但 0.85.0 新增的记录没有配套开关：

```
no switches (control)          record=WRITTEN  rule-hits=written
DISABLE_RULE_HITS_LOG=1        record=WRITTEN  rule-hits=suppressed   ← 半个守卫
DISABLE_SESSION_START_HOOK=1   record=absent   rule-hits=suppressed
DISABLE_CLAUDEMD_HOOKS=1       record=absent   rule-hits=suppressed
```

`hook_record_plugin_root` 无自身守卫（只拒引号、反斜杠、换行），调用为 `2>/dev/null || true`，完全静默；
而最便宜的探测臂恰是写入者——`session-start-check.sh:50` 的记录动作位于 `source == "compact"` 早退之上。
**建议修法**：`DISABLE_HOOK_ROOT_RECORD=1`，置于 `DISABLE_RULE_HITS_LOG` 旁的 env-clear 块。

**同类第二例**（r16-hooks 自查发现）：`version-sync.sh:49` 的哨兵键在 `${TMPDIR:-/tmp}` 上，
`HOME=` 重定向不到它，故一次全沙箱的 45 次扫描仍在共享 `/tmp` 留下 `claudemd-sync-sweep-sid`。

**处置**：记录内容存档后删除（用户授权）。回落路径经验证：`hook-drift` 由
`installed hooks match source (via hook-fired at … (sid repro-r16))` 变为 `skipped (self-compare)`。

### 7.2 单次运行不是对间歇性现象的复现

lead 对 H-1 的首次复核每臂只跑一次，抽中 7% 的快路径，因而错误地报告"不复现"。
r16-hooks 的原始三次采样全部命中慢路径，读起来像确定性现象，同样未建立分母。
**两侧都缺分母**。最终形态见 6.8。

### 7.3 标题跑赢正文，读者就会拿到错的数

H-1 的作用域限定词（`timeout(1)` 存在时该分支不可达）本在 r16-hooks 的报告正文里，
但不在它的标题与给 lead 的摘要里，而 lead 是照摘要行动的。
由此产生的"每次 `git push` 多付 2 秒"对任何装有 coreutils 的机器都是错的。

### 7.4 并行审计员通过全局状态互相污染测量

五个 agent 在同一宿主上并行，经由全局 `/tmp` 与 `~/.claude/` 互相影响。本轮出现两次：
实盘 `hook-root.json`（§7.1），以及 `sandbox-disposal` 测试的红
（**注**：最初归因于审计员沙箱，经 r16-hooks 以 grep 证据纠正——三次失败所涉目录全部来自
仓库自身代码 `doctor-hook-tests.js` 与 `clean-residue.test.js`，故日常触发条件是
"在 hook 套件运行时跑 `/claudemd-doctor` 或本仓库 node leg"，比"第二个审计员"常见得多）。
