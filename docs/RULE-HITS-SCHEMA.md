# rule-hits JSONL schema

File: `~/.claude/logs/claudemd.jsonl`
Format: one JSON object per line. Append-only. Size-capped rotation at 5 MB
(see `hooks/lib/rule-hits.sh`).

## Fields

| Field | Type | Description |
|---|---|---|
| `ts` | string (ISO-8601 UTC, Z-suffix) | timestamp of row creation |
| `hook` | string | hook name — see "Events" table for valid emitters |
| `event` | string | event class — see "Events" table |
| `project` | string | project identifier: `$CLAUDE_PROJECT_DIR` (or `$PWD` fallback), encoded per-character by `hook_encode_project` (`hooks/lib/rule-hits.sh:28`) — every character outside `[A-Za-z0-9-]` becomes `-`, not just `/` and `.` (so `_`, spaces and non-ASCII collapse too, and a multi-byte character becomes a single `-` regardless of how many bytes it occupies). Worked example, executed against both encoders by `tests/hooks/rule-hits.test.sh` case DOC-1: `/home/项目x` → `-home---x`. A byte-wise reimplementation yields `-home-------x` instead and will not find the directory; that form was the bash side's own behaviour until the 2026-07-17 audit replaced it. One residual: a non-BMP character such as an emoji yields two `-` from the JS encoder, which counts UTF-16 units, against one from the bash encoder, which counts codepoints. This is the same encoding Claude Code applies to `~/.claude/projects/<encoded-cwd>`, which is why a join across the two works; a consumer that reimplements it as "`/` and `.` → `-`" computes a different key and silently matches nothing. Empty string when neither var is set. Added v0.6.2. |
| `session_id` | string \| null | Claude Code session identifier extracted from stdin EVENT JSON `.session_id`. `null` for rows written before v0.9.33 (added then). Every emitter hook populates it as of v0.9.34 — the count said 12, which was the v0.9.34 inventory and not today's (2026-08-29 audit R10-21f); read it off `hooks/` rather than from here. |
| `tool_use_id` | string \| null | Per-invocation tool use ID (format `toolu_[alnum]`) from stdin EVENT JSON `.tool_use_id`. Only PreToolUse / PostToolUse events carry this — Stop / SessionStart / SessionEnd / UserPromptSubmit emit `null` (no per-tool context). Drives audit `unique_invocations` dedup. Key (extended v0.23.21) is `(ts, hook, session_id, tool_use_id, event, extra)`: BYTE-IDENTICAL rows twice ⇒ true single-invocation double-fire (registration / lib bug); different `tool_use_id` at same ts + same session_id ⇒ Claude fast-retry after deny, NOT a duplicate. Multi-emit hooks (`pre-bash-safety` logs one row per matched pattern in a compound command) legitimately repeat the quadruple with differing `extra` — the `event`+`extra` key keeps those distinct; a byte-identical residual can still arise from one command repeating the same pattern, so confirm against the source command before treating a `pre-bash-safety` `_real` as a bug. Added v0.9.34. |
| `spec_section` | string \| null | rule ID the row counts toward, the key `/claudemd-audit` groups by (several predate spec v9: see "Spec section taxonomy"). `null` for plugin-internal events (bootstrap, version-sync, upstream-banner) and for rows written before v0.7.0. See "Spec section taxonomy" below. Added v0.7.0. Audit `bySection` (v0.9.37+) splits null-section rows by cutoverTs: pre-cutover ⇒ `(unset-historical)`, post-cutover ⇒ `(unset-current)`. |
| `hook_version` | string \| null | semver of the plugin build whose hook wrote the row (plugin-root `package.json`, cached per process). Stratifies rows written by a stale registered hook dir (other live CC windows run old hooks until restart) out of calibration windows. `null` for rows written before v0.56.0 or when the manifest is unreadable (fail-open). Added v0.56.0 (2026-07-25 audit ARCH-3). |
| `extra` | any | hook-specific payload (object / null / string). For `memory-read-check`: `deny` rows carry `{missing: string[], match_count: number, tags: {[file]: string[]}}` (`match_count` = total MATCHES in MEMORY.md scan = MISSING.length + already-Read subset; added v0.9.36; `tags` maps each missing file to the index tags that matched the command, spaces removed as the matcher compares them; added after 0.119.0, older rows have no `tags`); `bypass-escape-hatch` rows carry `{token: string}` plus optional `bypass_reason: string` when `[skip-memory-check: <reason>]` form is used (added v0.9.36). |

must have a matching `hook_record` call in source, and every emission in

## Spec section taxonomy

`spec_section` carries the spec section identifier each event maps to. The
mapping is compile-time per (hook, callsite); `extra.matched` keeps the
per-pattern detail. Hooks that don't enforce a spec rule (session-start
bootstrap / upstream-banner / user-prompt-submit version-sync) emit `null`.

The values are log keys, not pointers into the current spec. Each was fixed
when its callsite was written, and several no longer match spec v9: the CI
baseline rule behind `§7-ship-baseline` is in §12 Ship, and v9 has no §8.V4,
§11 or §2.2 for `§8.V4`, the `§11-*` keys and `§2.2-modules`. They are kept
so that rows from before and after v9 group under one key, and
`spec/hard-rules.json` uses the same strings as its rule IDs.

| Hook | Event | spec_section |
|---|---|---|
| `banned-vocab` | `deny` / `bypass-escape-hatch` | `§10-V` |
| `ship-baseline` | `pass` / `pass-known-red` / `pass-known-red-incmd` / `pending-no-baseline` / `deny` / `deny-repeat` | `§7-ship-baseline` |
| `pre-bash-safety` | `deny` | granular per triggering pattern: `§8-rm-rf-var` / `§8-npx` / `§8-curl-sh` (one deny row per section present; untagged hits fall back to `§8`) |
| `pre-bash-safety` | `bypass-escape-hatch` (`allow-rm-rf-var`) | `§8-rm-rf-var` |
